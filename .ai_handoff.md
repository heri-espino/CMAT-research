This is the main continuity file for future AI sessions. Read it before changing scientific code, interpreting results, rebuilding reports, or editing manuscripts.

## 1. Repository model

`heri-espino/CMAT-research` is the canonical private repository.

- `main` is the stable source of truth.
- Branches are short-lived task workspaces, not permanent project categories.
- Scientific chain: `controlled data -> code/ -> analysis/ -> reports/ and papers/`.

## 2. Privacy boundary

Do not commit administrative Excel files, row-level student/advising microdata, direct identifiers, HMAC keys, secrets, credentials, or unreviewed identifying free text.

SHA-256 is used for integrity/provenance, not anonymisation. HMAC pseudonymisation and anonymisation are distinct concepts.

The private repository may archive literature PDFs/assets for internal continuity, but a public research release should not automatically redistribute copyrighted PDFs or administrative microdata.

## 3. Administrative data interpretation

### Academic records

The academic table provides the student's official degree programme and final course outcomes. CMAT visit records contain the institutional student ID; that ID links visits to the academic table.

Do not describe the Forms-declared degree as the basis of the main adjustment models. The official academic degree associated with the real academic attempt is the relevant degree field.

Academic rows are not automatically real attempts: degree changes/revalidations can replicate already-passed courses under another programme. Historical audits found post-pass repeated rows and same-student/course/period multi-career rows; preserve the real-attempt/revalidation logic.

### CMAT visits

Each Google Forms record is one recorded advisory visit. There is no duration measure. Multiple same-day records can be legitimate because students can attend different professors/shift blocks; do not label repeated same-day attendance as manipulation without evidence.

For the PPA analysis, the primary operational count is any CMAT registration during the MU period regardless of declared topic; a course-specific sensitivity can use MU-tagged/Calculus-tagged visits.

## 4. PPA interpretation

PPA1 is a first-year institutional participation requirement/incentive context. CMAT activities can contribute toward PPA1 credit/points, but do not equate three CMAT records with three PPA points.

The study operational threshold is **3 CMAT visit records during the MU term**.

Primary study assumption: students usually complete PPA1 in first semester, so MU is treated as the incentive-linked context and later Calculus as a context where that same PPA1-linked CMAT incentive is treated as no longer applying. Delayed PPA1 completion is theoretically possible; this is an assumption, not an observed individual completion date.

There is no exogenous PPA treatment variation. The research does **not** identify a causal effect of PPA.

## 5. Outcomes and classroom standardisation

Pass threshold: 7.5.

BV, RT and BA are adverse/non-passing states. EQV/REV/AC are administrative/non-comparable states.

Classroom is defined as:

`professor × same course × same academic period`.

For numeric classroom performance:

`Z_ic = (Y_ic - mean_classroom_c) / sd_classroom_c`.

A longitudinal difference `DELTA_Z = Z_CALC - Z_MU` is a change in relative classroom position, not a raw-grade difference and not a causal treatment effect.

### Important methodology correction still to integrate into the canonical code

The intended primary continuous-outcome treatment of BV/RT/BA is classroom-level KDE imputation from observed numeric grades below 7.5 using `scipy.stats.gaussian_kde(..., bw_method=None)` (SciPy default Scott bandwidth). Draws must remain in `[0,7.5)`. If the sub-7.5 pool is degenerate, empirical resampling is appropriate; use `Uniform(0,7.5)` only when a classroom has no observed numeric grade below the threshold.

Historical v8 code used a different custom KDE/Silverman implementation. Do not claim the code is fully reconciled until this is ported, tested and canonical outputs are regenerated.

## 7. Key documented longitudinal Paper 1 results

For the strict primary cohort (`N=3,241`), later Calculus CMAT use by MU-period visit group was documented as:

- 0 visits: 426/2470 = 17.25%.
- 1–2 visits: 205/472 = 43.43%.
- exactly 3: 56/103 = 54.37%.
- 4+: 131/196 = 66.84%.

Global 4×2 Pearson: chi-square(3)=392.47, p≈9.47e-85, Cramér V=0.348.

Exactly 3 vs 4+ documented contrast:

- risk difference (4+ minus 3) = 12.47 percentage points;
- Newcombe 95% CI approximately [0.92, 23.90] pp;
- RR≈1.229;
- OR≈1.691.

Interpret as a pattern compatible with threshold-limited vs more persistent use, not evidence that the incentive caused habit formation.

Adjusted persistence models historically showed strong predictive associations relative to 0 MU visits (approximately OR 3.53 for 1–2, 4.84 for exactly 3, 9.82 for 4+), conditional on prior classroom-relative performance, official MU degree and MU period with classroom-clustered SEs. These are observational associations.

The piecewise visit-count model is descriptive, **not RDD**, because visit count is student-controlled.

Later Calculus performance associations historically remained positive after adjustment for prior MU Z, degree and period, but performance is secondary to persistence in Paper 1.

## 8. Paper 2 current empirical interpretation

Paper 2 studies contemporaneous CMAT use and classroom-relative first-MU performance.

The later methodology work expanded visit groups to `0 / 1 / 2 / 3 / 4+` and all ten pairwise comparisons, using Games–Howell plus adjusted classroom/degree models with clustered SEs and Holm multiplicity correction.

The current interpretation to protect is:

**the robust separation appears primarily between 0 visits and positive use; differences among 1, 2, 3 and 4+ do not support a clean monotone dose-response.**

Exact visit-count analyses (0–12) and sparse-tail sensitivity should be treated descriptively; an apparent slope driven by very sparse high-count groups is not a strong dose-response result.

## 9. Temporal and degree-programme extensions

Later methodology work added periodicity analyses for:

1. all CMAT activity; and
2. first-MU students during their own MU period.

Use daily counts, ACF/periodogram/peak methods descriptively. Do not claim peaks are exams without a validated exam calendar.

Degree-programme analyses should distinguish populations (all relevant CMAT / first MU / Calculus as applicable), show average classroom-relative Z and CMAT-use rates by official degree, and can use ecological Pearson/Spearman scatterplots. Do not infer individual-level relationships from programme-level correlations.

Small degree cells may be excluded from specific inferential summaries (historically a threshold such as n>=30 was used), but must not be described as deleted from the underlying data; list/retain them for audit.
