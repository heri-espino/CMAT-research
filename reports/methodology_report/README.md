# CMAT methodology report

This directory is an **atomic methodology/statistical-review workspace**. It contains the report source, retained aggregate tables/figures, brainstorming notes, provenance and its own thin execution entry point.

It does **not** own a separate scientific implementation: reusable functions remain in the repository-level `code/` package.

## Atomic structure

```text
reports/methodology_report/
├── README.md
├── code/
│   └── methodology_report.py      # thin local entry point
├── tables/                        # retained aggregate CSV + LaTeX snippets
├── figures/                       # retained aggregate figures
├── notes/                         # report-level brainstorming/future analyses
├── provenance/                    # report-specific historical/method records
├── build/                         # disposable local generated outputs; ignored by Git
├── methodology_report.tex
├── methodology_report.pdf
└── referencias.bib
```

## Root-code dependency rule

`code/methodology_report.py` should only locate/import the canonical root-code package and invoke the report recipe. Do not add reusable statistics, cohort definitions, transformations, models or plotting functions here.

The implementation used by this report lives in root `code/`, principally:

- `../../code/src/visitas_analysis/study/methodology_pipeline.py` — analysis sequence;
- `../../code/src/visitas_analysis/study/extended_methodology.py` — methodology extensions;
- `../../code/src/visitas_analysis/study/methodology_plots.py` — figures;
- `../../code/src/visitas_analysis/reporting/methodology_report.py` — LaTeX table rendering;
- `../../code/src/visitas_analysis/reporting/methodology_build.py` — build/validation orchestration.

If the report needs a new scientific function, add it to root `code/`, test it there, regenerate `code/FUNCTION_INDEX.md`, and only then call it from the local runner.

## Reproducible build

From the repository root:

```bash
# Validate paths/import structure without controlled data
python reports/methodology_report/code/methodology_report.py --check

# Run with explicit controlled data extracts
python reports/methodology_report/code/methodology_report.py \
  --materias /controlled/path/Materias.xlsx \
  --asesorias /controlled/path/Asesorias.xlsx

# Regenerate, stage, and compile the report
python reports/methodology_report/code/methodology_report.py \
  --materias /controlled/path/Materias.xlsx \
  --asesorias /controlled/path/Asesorias.xlsx \
  --compile
```

The stable runner imports the methodology pipeline/functions from root `code/`, executes them in the fixed report recipe, stages generated CSV/PNG assets into this directory, and rebuilds `latex_*.tex` table snippets.

Disposable intermediate outputs and the build manifest live under:

`build/`

This directory is ignored by Git. Reviewed/staged report assets live in `tables/` and `figures/`.

To generate working outputs without replacing the retained report tables/figures:

```bash
python reports/methodology_report/code/methodology_report.py \
  --materias <academic-file> \
  --asesorias <visits-file> \
  --no-stage
```

## Narrative prose after a data update

Tables, figures and LaTeX table snippets are regenerated computationally. `methodology_report.tex` still contains explanatory prose with embedded numerical values; after a new data extract changes results, review those sentences against regenerated outputs before treating the compiled PDF as updated.

Do not manually change a numerical claim without tracing it to the corresponding generated output.

## Methodological content

The report documents, among other items:

1. official degree programme from academic records linked by student ID;
2. BV/RT/BA continuous imputation using within-classroom KDE below 7.5 with SciPy/Scott default and explicit fallbacks;
3. exact performance groups `0/1/2/3/4+`, Games–Howell pairs and adjusted FE+Holm pairs;
4. exact counts 0–12 with sparse-tail diagnosis;
5. temporal/periodicity analyses for CMAT and first-MU populations;
6. degree-programme summaries and use-versus-performance analyses;
7. the N=4,211 future-Calculus progressor sensitivity;
8. limitations involving ecological inference, cluster-robust inference, multiplicity, selection and propensity-score approaches.
